# 블록 설계 원칙

블록 하나에는 작성자가 이해할 수 있는 콘텐츠 목적 하나를 부여합니다. 예제의 안내 카드는 제목과 본문이 함께 이동하는 안내입니다. 색상이나 글꼴만 다른 문단은 같은 문단을 CSS로 표현할 수 있습니다.

## 편집 요구에 맞춰 데이터를 모델링합니다

| 편집 요구 | 적합한 모델 |
| --- | --- |
| 제목, URL, 선택지처럼 구조가 정해진 값이 하나의 단위로 움직입니다. | 자식이 없는 atom과 `attrs`를 사용합니다. 안내 카드와 FormKit 질문이 이 형태입니다. |
| 작성자가 문장에 링크나 서식을 넣거나, 문단과 목록을 중첩합니다. | `spec.content`로 편집 가능한 콘텐츠를 정의합니다. `spec.toDOM`의 콘텐츠 홀 `0` 또는 ProseMirror NodeView의 `contentDOM`을 사용합니다. |
| 여백, 글꼴, 색이 앱이나 테마에 따라 바뀝니다. | CSS에서 표현합니다. 작성한 내용과 함께 저장하거나 읽기 화면에 재현할 의미가 있는 옵션만 스키마에 추가합니다. |

atom은 한 단위로 선택하고 옮길 수 있는 블록입니다. 문단 안에서 커서 이동과 서식을 유지해야 하는 단어는 텍스트와 mark로 남겨 두세요. 안내 카드 본문에 서식과 링크가 필요해지면 문장 전체를 문자열 속성에 넣는 모델부터 재검토하세요.

## 저장할 데이터와 편집 상태의 수명이 다릅니다

스키마와 검증을 통과한 JSON이 저장할 콘텐츠를 정의합니다. 커서, 선택 상태, 열려 있는 설정 패널과 입력 중 임시 문자열은 화면에서 관리합니다. 앱의 브랜딩과 전송 방식도 문서 외부에 둡니다. 폼 답변은 문서의 질문 정의와 별도로 수집하고 `fieldId`에 연결합니다.

블록 타입 이름과 속성이 저장 형식의 일부입니다. 기존 문서와 호환되는 추가 속성에는 유효한 기본값을 지정하세요. 타입명이나 속성의 의미를 바꿀 때는 앱에서 이전 JSON을 새 형식으로 변환한 뒤 검증하고 저장합니다. 이전 문서 예제로 변환을 확인하세요. 코어는 등록되지 않은 블록이나 지원하지 않는 버전을 오류로 돌려줍니다.

## 주요 내용은 작성하는 자리에서 수정합니다

안내 카드의 제목과 본문, 질문 이름과 선택지는 블록 안에서 입력합니다. 가끔 바꾸는 이미지 너비 같은 설정은 선택한 블록 가까이에서 엽니다. 선택, 이동, 복제, 삭제와 실행 취소는 코어의 명령과 기록을 사용합니다. 이동과 편집은 블록 ID와 고유 속성 ID를 유지합니다. 생성과 복제는 새 ID를 받습니다.

입력 중에는 빈 제목처럼 저장할 수 없는 상태가 생길 수 있습니다. 컴포넌트에 초안을 유지하고 검증된 값만 문서에 반영하세요. 포커스를 떠날 때 유효한 값으로 복원하거나 오류를 표시합니다. 한글 조합 중에는 입력 값을 유지하고 조합이 끝나면 커밋하세요. 각 컨트롤에 접근 가능한 이름을 붙이고 포커스, 입력 커서, 실행 취소 단축키를 확인하세요.

## 같은 정의를 서버와 브라우저에서 씁니다

스키마, 메뉴, 검증과 HTML 출력은 DOM 없이 가져올 수 있는 확장 모듈에 둡니다. React 컴포넌트에는 편집 UI를 둡니다. 서버의 `parseDocument`와 `renderHTML`, 브라우저 편집기, 폼에 같은 블록 정의를 등록하세요. 브라우저용 FormKit은 서버용 FormKit과 같은 노드 정의에 편집 UI를 연결합니다.

직접 HTML을 만들 때는 사용자 텍스트와 속성값을 `escapeHTML`로 처리하고 URL은 `safeURL`로 검증하세요. `spec.toDOM`을 HTML 출력에 재사용할 경우 코어의 배열 직렬화가 텍스트와 속성값을 이스케이프합니다. 확장과 편집 컴포넌트는 앱에서 작성한 코드로 등록합니다. 외부에서 받은 JSON은 `parseDocument`로 검증하세요.

## 블록 변경을 검토할 때 확인할 것

- 슬래시 메뉴로 추가한 뒤 본문에서 편집하고 실행 취소합니다. 한글 조합과 키보드 이동 중에도 커서와 포커스가 유지되는지 확인합니다.
- 블록을 옮기고 복제한 뒤 JSON을 저장하고 다시 엽니다. 이동한 블록은 ID가 유지되고 복제한 블록은 새 ID를 받는지 확인합니다.
- 잘못된 속성과 예전 문서 예제를 파서에 전달합니다. 각각의 오류와 하위 호환을 확인합니다.
- Node.js에서 문서를 출력해 구조와 이스케이프를 확인합니다. 편집 UI 없이도 제목과 본문이 전달되어야 합니다.

[안내 카드 만들기](extensions.md)에서 정의, 편집 화면과 서버 출력을 연결할 수 있습니다.
